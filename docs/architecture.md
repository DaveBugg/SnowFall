# Архитектура SnowFall

## Потоки

```
 UI-поток (message loop)                 Поток симуляции              Поток рендера
 ───────────────────────                 ───────────────              ─────────────
 AppHost: трей, hotkeys, питание,        SimRunner                    OverlaySystem
 сессия, настройки                         World::step(1/60)            D3D11 + DComp
 WindowTracker ──DesktopLayout──────────►  (mailbox, коалесцируется)    по overlay на монитор
 InteractionController ──InputEvent─────►                                 │
   (WH_MOUSE_LL только в режиме)           buildSnapshot ──FrameSnapshot──┤ (SnapshotExchange,
   ◄──────────── hitRegions ───────────────────────────────────────────────┘  shared_ptr, latest)
 SettingsWindow / TrayIcon
```

* **UI-поток** — все HWND приложения, `SetWinEventHook`, `RegisterHotKey`, низкоуровневый
  мышиный хук (только в режиме взаимодействия), сообщения питания/сеанса. Тяжёлой работы нет.
* **Поток симуляции** (`core/runtime/sim_runner.cpp`, ожидание и курсор — через хуки платформы) — фиксированный шаг 1/60 с, не более 3 шагов
  catch-up, после >250 мс простоя (сон, отладчик) пропущенное время не симулируется.
  Раскладка окон и настройки передаются через latest-value mailbox: при перетаскивании окна
  применяется только последняя раскладка. Снимки — пул `shared_ptr<FrameSnapshot>`,
  повторно используемых, когда рендер их отпустил (без аллокаций в установившемся режиме).
  При паузе пользователя эмиссия останавливается, летящие снежинки досыпаются ~14 с, потом
  поток спит на событии.
* **Поток рендера** (`rendering/d3d11`) — берёт последний снимок, экстраполирует частицы по
  скорости до момента кадра (плавность при 60 Гц независимо от фазы симуляции), рисует
  сугробы (кешированные меши по `version`), объекты, частицы, курсор инструмента. Vsync,
  кап 30/60 FPS, восстановление после device loss.

  simulation/         World (фасад), погода, частицы, куски, салют
  surfaces/           поверхности, карта высот, вычитание прямоугольников (окклюзия)
  interaction/        инструменты, снежки и снеговики, машинка, сосульки, кляксы
  settings/           JSON, миграции, sanitize(), грамматика горячих клавиш
  runtime/            поток симуляции (SimRunner), PerformanceGovernor
  i18n/               таблица строк интерфейса RU/EN
  diagnostics/log.h   интерфейс журнала (реализация — в платформе)
  tests/              юнит-тесты ядра
platform/windows/     Win32 + D3D11/DirectComposition
  app/                AppHost, поток симуляции, ввод, PerformanceGovernor, UI (app/ui)
  tracker/            WindowTracker (EnumWindows + WinEvent hooks)
  rendering/d3d11/    OverlaySystem, шейдеры

Правило: всё, что может работать без ОС, живёт в `core/` и тестируется на любой платформе.
Платформа реализует: окна поверх экрана и рендер, слежение за окнами (`DesktopLayout`),
ввод (`InputEvent`), хранение файлов (`SettingsStore`), журнал, трей и интерфейс.

## Координаты

Всё, что передаётся между модулями, — физические пиксели виртуального рабочего стола
(могут быть отрицательными). Процесс Per-Monitor-V2 DPI aware. Значения настроек
«px при 96 DPI» умножаются на `dpiScale` монитора/окна. Рендер вычитает начало монитора.

## Поверхности и сугробы

* Источник — `DesktopLayout.windows` (front-to-back). Окно `App` → поверхность на верхней
  кромке; `Taskbar` → поверхность на верхней кромке панели; низ каждого монитора без панели
  задач → поверхность «низ экрана». `Occluder` (меню, всплывающие, исключённые программы)
  снег не держат, но закрывают.
* Идентичность — `WindowId` (счётчик сессии, не HWND). Карта высот в локальных координатах
  окна, поэтому перемещение окна переносит сугроб без изменений; resize обрезает/дополняет;
  свёрнутое окно — сугроб сохраняется скрытым; закрытое — снег осыпается частицами.
* Окклюзия: видимые части полосы сугроба = полоса − прямоугольники всех окон выше (общее
  вычитание прямоугольников). Колонка принимает снег, только если точка над ней видима.
  Рендер рисует сугроб только внутри этих clip-прямоугольников — снег не рисуется поверх
  перекрывающих окон.
* Коллизия частиц — пересечение отрезка перемещения за шаг с линией верха снега (без
  tunneling).

## Пауза и исключения

`PerformanceGovernor::decide()` — чистая функция: пауза пользователя (сугробы видны, эмиссия
стоп), «Скрыть всё», полноэкранное приложение, блокировка сеанса, сон, отказ графики →
overlay скрыт и поток симуляции заморожен. Батарея/экономия энергии → 30 FPS и меньше частиц.

## Приватность

Нет сетевого кода, телеметрии, инъекций, драйверов, служб, повышения прав. Содержимое,
заголовки и пиксели чужих окон не читаются (единственное чтение пикселей экрана — в
self-test'ах, и только внутри собственного тестового окна). В журнал пишутся только числа,
HRESULT и состояния.
